CRITICAL FINDING: System is unsuitable for live trading at any scale without fixes.

7 CRITICAL VULNERABILITIES IDENTIFIED:

1. POLYGON API → SINGLE POINT OF FAILURE
   - No fallback source wired
   - Signal generation halts entirely if offline
   - Fix: Wire yfinance fallback (2 hours)
   Status: ❌ CRITICAL

2. yFINANCE CALLS → NO TIMEOUT ENFORCEMENT
   - Can hang indefinitely (default system timeout = many minutes)
   - Used in 4 scorers (momentum, quality, earnings, estimate_revisions)
   - Timeout → score defaults to 0.5 (neutral), signal degrades
   - Fix: Wrap yfinance calls with 15-second timeout (3 hours)
   Status: ❌ CRITICAL

3. CONGRESS TRADES → 6-HOUR STALE DATA WINDOW
   - If API fails, serves stale trades for entire trading day
   - Quiver API has no fallback source
   - Fix: Add SEC EDGAR fallback (4 hours)
   Status: ❌ HIGH

4. EARNINGS CALENDAR → 24-HOUR CACHE TOO AGGRESSIVE
   - Pre-earnings earnings dates change frequently
   - Modifiers applied to stale dates cause signal errors
   - Fix: Reduce TTL to 6 hours (2 hours)
   Status: ❌ HIGH

5. NO STALENESS MONITORING
   - Can serve days-old cached data without alerting
   - Users unaware of data freshness degradation
   - Fix: Track data_published_at in cache layer (4 hours)
   Status: ❌ HIGH

6. NO CIRCUIT BREAKER
   - Multiple simultaneous API failures cause cascading signal degradation
   - No hard stop when data quality below threshold
   - Fix: Implement circuit breaker state machine (TBD in Phase 2)
   Status: ⚠️  MEDIUM

7. NO DATA QUALITY REPORTING
   - Response doesn't include freshness score or warnings
   - Users get 0.62 signal without knowing if data is stale
   - Fix: Add data_quality dict to /analyze response (2 hours)
   Status: ⚠️  MEDIUM
